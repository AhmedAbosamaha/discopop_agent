The argument the experiments have to carry

The thesis makes one move: a dependence DiscoPoP reports is read as a diagnosis, not a limit, and a language model re-encodes the code so the dependence is gone. That move creates two problems annotation tools never face. The evaluation is built to show the move pays off, and that both problems are handled.

C1 · COVERAGERestructuring parallelizes what DiscoPoP alone cannot.

Measured against DiscoPoP's own suggestions pushed through the same gate.

C2 · TRUSTA gate strong enough to permit rewriting — and where it is still blind.

Every accepted change is re-judged independently; unsafe acceptances are counted, never averaged away.

C3 · COSTDependence evidence stays valid across edits without re-profiling from scratch.

Fast refresh and model reconstruction, measured for fidelity and for what they save at scale.

How Chapter 6 reads: first the whole system, then one region through each stage

After the instruments are proven and the whole agent is measured once, the chapter follows a single region through the agent in the order the agent handles it. Each section asks one question — what does this stage contribute, and what would happen without it? — so every experiment has a place in the story and none stands alone.

  1. 6.1 Prove the instruments T0.1–T0.7

    Sizes, DiscoPoP's own variation (in its profile labels and in its explorer), timing noise on a shared host, whether the correctness oracle can see a wrong program at all — opening with the seidel-2d case, where it could not — and where each program's runtime goes, which fixes the region filter.

  2. 6.2 The whole system — RQ1, RQ3 E1 · E11

    What the agent delivers against DiscoPoP alone, the Polly auto-parallelizer and expert OpenMP, across kernels and applications; then against the closest published system, RepoOMP, on identical NPB programs.

  3. 6.3 Stage 1 · Where to look E9

    Ranking by measured time saved versus a static proxy: are model calls spent where the runtime is?

  4. 6.4 Stage 2 · What the model is told, how often it may try, and how strong it is — RQ4 E2

    DiscoPoP's evidence against the gate's feedback, crossed with model strength.

  5. 6.5 Stage 3 · Who judges the result — RQ2, C2 E7 · E10

    The gate as a classifier: its error rate, what each stage uniquely catches, and how the input shapes its verdicts; then the speed check — does it keep changes that do not pay off out of the program, and at which size can it judge speed at all?

  6. 6.6 Stage 4 · Who writes the pragma, and how evidence survives the edit — RQ5–RQ7, C3 E3 · E4

How regions are ordered (§5c of the record). The agent scores a region by Amdahl's predicted saving, T·f·(1 − 1/(P·e)). T, P and e are one value for the whole run, so the order equals the order of runtime share f: it is the upper bound of what each region could save, not a prediction that accounts for whether it can be parallelised. That is kept deliberately, as the only ordering with no estimated parameter; whether a region can be parallelised is left to the model, the gate and the budget. T0.5 shows the order is the same at the agent size and the verification size (top loop identical in 22 of 23 benchmarks).

How every trial is scored

The agent's own verdict is logged but never counted. The harness rebuilds the original and the final source and decides one outcome per trial. Results then go into a 2×2 whose every cell is reported:

Actually correctActually wrong
AcceptedFASTER / parallel-not-faster — speedup is reported only here. On the 8 kernels T0.1 found too short to time at any runnable size: parallel-speed-not-measurable — counted for correctness, excluded from every speed statistic and from H1, ratios listed separately as not being speedupsBROKEN — unsafe acceptance. Reported as a count with every case named, target zero
RejectedOver-caution — detectable only on kernels with a known parallel form (category A/B hypotheses, checked by hand)True negative — the category C kernels exist to make this cell visible

SCAFFOLD_MODIFIED sits outside the 2×2: the rewrite changed the instrument (timer, perturbation or digest), so neither verdict measures the program. It is checked before correctness and speed, listed, and never counted as a result.

Statistics stay proportionate: medians and IQRs, Mann–Whitney U for paired arm comparisons, no p-value on a count of unsafe acceptances, geometric mean if speedups are ever aggregated.

Statistics

  • Repeats sized to the claim: ×5 for the headline model-driven comparisons (E1 core, E2), ×3 for E3/E4, ×1 for breadth runs — the variance is the model's; the pipeline without a model is deterministic (measured, zero variance over 10 runs).
  • Paired by benchmark: Wilcoxon signed-rank on per-benchmark medians for arm comparisons; Cliff's delta as effect size.
  • Uncertainty shown, not implied: Wilson 95 % intervals on rates, bootstrap intervals on median speedups.
  • Several tests, one error budget: Holm–Bonferroni across H1–H7.
  • Unsafe acceptances are counts, each case named with its diff — never a p-value.

Reproducibility and qualitative analysis

  • Every run records both repos' commit and diff hash, full model ids, SDK/CLI versions, compiler, host load; the server checkout is proven identical to the local one before each experiment.
  • Every run is archived in the repository: agent/benchmark archive copies a run's trials.csv, gate_failures.csv, figures, tables, every trial's record, log, diff and candidate patches, and the program every trial started from into the tracked agent/results/<run>/ (sha256 per file in ARCHIVE.json; INDEX.md lists the runs; README.md maps thesis material to files). server.sh fetch archives what it fetches; the one manual step is the commit. A number that is not in agent/results/ does not exist. agent/benchmark plots regenerates every figure and table from the archived data.
  • Cost is reported in time, model calls and tokens (read from the SDK's usage record — an agent addition).
  • Every BROKEN trial and a random sample of rejected rewrites are coded into a failure taxonomy with a written codebook, so the chapter explains why, not only how often.

E8

How deep should restructuring go?

RQ8 · C1 · C3

A kept rewrite often exposes new loops. With --restructure-depth 0 — the default, and every other experiment here — those loops get DiscoPoP's pragmas at most, never a second rewrite. Depth decides how far the agent may chain restructuring, and it changes cost too: before a deeper level the agent pays for a full instrumented re-profile and re-measures runtimes, and fast refresh is used only at the last level.

What a deeper level can see (D2′). After a kept rewrite the parallel constructs it created are covered with their measured share; the rewritten function itself stays a candidate only if measurable sequential time remains in it (its share minus the covered loops', above the 1 % floor), and any loop inside a parallel construct is never a candidate. Before Fix 76 the whole edited region was covered, so depth 1 and 2 could never receive a candidate — the three arms would have been identical.

The risk E8 must show honestly

Each level moves the source further from the original, and a rewrite that needs its own pragma just to break even is worth less than none. The verify step compares against the original program, so compounding serial cost shows up in the result rather than hiding in per-level gains.

E10

Does the speed check keep unnecessary changes out?

RQ2 · C2 · gate

The speed check exists so that a change which does not pay off is not kept: the gate's performance stage (≥ 1.1× measured), Phase B's marginal check (a pragma that costs more than it saves is dropped) and Settle's final check (the finished program must not be slower than the original). Every other experiment runs with it off (--no-require-speedup): at the agent's size the kernels take 0.06–15 ms, below the cost of starting threads, and the check would judge noise. E10 studies the check where it can measure — profiling and every correctness check stay at the agent size, and only the timed builds use a larger per-kernel size (--timing-cflags, an agent addition).
