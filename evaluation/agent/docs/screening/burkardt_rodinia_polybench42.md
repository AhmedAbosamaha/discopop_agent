## Conventions used in every row
- **Class is predicted from code only.** R = DiscoPoP alone cannot parallelise the hot loop as written. **R\*** = DiscoPoP would likely report a pattern but the gate must reject it (e.g. output order). A / D as in the brief.
- **H13 vs H13-trivial.** PolyBench, lud_base and most Burkardt code declare `int i,j,k` / temporaries at function scope, so any naive `parallel for` races on inner indices. That case is marked **H13-trivial** (a `private` clause fixes it). **H13** means the race or output change is still there after loop indices and plainly private scalars are privatised.
- **E8 has three tiers.** **E8-strict**: no single-step correct form gives more than a trivial speedup. **E8-as-shipped**: the published expert used 2+ dependent steps, but a correct one-step form exists; that form is named. **E8-authored**: the published expert has no restructuring at all; the 2-step chain is proposed in this screen.
- **Defective shipped expert**: the published OpenMP version is racy or changes output. The property still stands, but the expert form has to be written or corrected. There is no clean external reference.
- Licenses: all Burkardt files say "distributed under the MIT license" in the file, except sgefa_openmp.c, functions_openmp.c and is.c, which have no license line; their program pages say MIT. Rodinia: UVA BSD-style (`rodinia/LICENSE`). PolyBench: OSU license, redistribution allowed if the notice is kept (`polybench-c-4.2/LICENSE.txt`).

## Summary

**C1 / E1 (predicted R + expert that goes beyond pragmas), IN:** nussinov 4.2 (P1), lu 4.2 (P4; cholesky P5 and ludcmp P6 are dups), multitask prime_table (B12), heated_plate (B4), julia_set (B9, induction substitution), dijkstra find_nearest (B1, argmin), satisfy (B19, **R\*** output order), bfs (R3), streamcluster (R20); doitgen 4.2 (P7) only if DiscoPoP does not privatise arrays. Already known from earlier: kmeans.

**H13 (substantive: survives privatising indices and scalars):** B1, B4, B7, B9, B12, B19, R3, R14 (top-k), R20, P1, P4/P5, P7, P8, P9. Everything else marked H13-trivial is fixed by a clause.

**E2-B1a (hidden dependence, and where the deciding fact sits):** streamcluster (another function sets `assign`), bfs (input file), kmeans (callee result, reviewed). The serial reading of random_openmp (callee writes `*seed`) and fire_simulation (libc `rand` state) qualify only with authoring or a seed fix; weak.
**E2-B1b (hidden independence):** fft step (offsets at the cfft2 call sites, another function), dijkstra update_mind (`connected[mv]=1` in the caller), hotspot3D (buffers allocated separately in main), particlefilter (callee `randu` writes a per-index seed). srad_v2, cfd, lavaMD and myocyte are weak (read-only index arrays from initialisation or input, or constants in the same function).

**E3 (outside DiscoPoP's set):** max (heated_plate; mandelbrot c_max, not hot), argmin (dijkstra), array reduction (streamcluster, kmeans), atomic write (bfs), scan (particlefilter CDF, multitask prime_table compaction), early exit (search, serial-only; prime_table), sections/tasks (multitask, myocyte), user-defined top-k (nn). **In-pattern `+` controls:** prime/quad/quad2d/schedule/openmp_test trio, jacobi_openmp, helmholtz, md, particlefilter sums, backprop errsum, srad_v1 ROI.

**E8 (priority).** E8-strict, where no single-step form gives real speedup (the expert *needs* the chain):
1. **nussinov 4.2**: skew, then interchange; the diagonal loop becomes Do-All. Exact int output. Strongest candidate.
2. **lu 4.2** (with cholesky 4.2 and ludcmp 4.2 as dups): merge the j loops, interchange k outermost, then distribute. Pragma-only on the j≥i loop caps near 2×. Bitwise-equal output is expected by argument, not run.
3. **multitask_openmp prime_table**: bound the while loop, fission test from compaction, then scan or ordered compaction.

E8-as-shipped, where a one-step alternative exists:
- **heated_plate**: fission, then private partial max. The alternative is a per-row max array.
- **Rodinia lud**: reorder, tile, then parallel blocks. The alternative is a pragma on lud_base's inner j loops.
- **nw**: tile plus wavefront. Rodinia ships no untiled serial form, so it would have to be written.

E8-authored (the shipped expert has no restructuring; the chain is proposed here):
- **bfs**: transpose, then pull. This counts only if atomics are excluded.

Among Burkardt pairs, only multitask prime_table *needs* two dependent steps; heated_plate's shipped expert *uses* two, but has a one-step alternative. Every other Burkardt pair is pragma-only or one restructuring.

**E9 (≥10 loop regions, none dominating): no verified candidate.** particlefilter (39 `for` loops) is plausible, but which loop dominates is unverified without a profile. helmholtz has 13 regions, but jacobi dominates. deriche has only 6 nests.

**Controls.** Class A: fft, jacobi_openmp, helmholtz, poisson, mxm (dup gemm), sgefa, hotspot3D, lud (base), backprop, deriche, heat-3d, adi, jacobi-1d/2d, syrk/syr2k, gemm 4.2, covariance/correlation, symm/trmm 4.2 (at j level). Class D: durbin 4.2 (outer k), sgefa and lud outer k, the random_openmp serial LCG stream.

**Defective shipped experts** (the property holds, but the reference must be written or corrected): mandelbrot_openmp (race on `c`, and normalisation changed), myocyte (`th_id` never set), streamcluster_omp (race on the `lower[]` scatter; Princeton license header dropped), bfs (same-value races), backprop (misused reduction). satisfy_openmp, random_openmp and ziggurat_openmp change output compared with serial.

**OUT, with reasons:** functions_openmp and hello_openmp (no computation); ziggurat_openmp and the random_openmp pair (output depends on thread count); heartwall and leukocyte (AVI input, multi-file); mummergpu (CUDA); b+tree and srad_v1 (input files, multi-file; A controls or dups only). Duplicates: mxm is gemm; poisson, heat-3d and jacobi-2d are the same stencil; quad2d, schedule and the openmp_test trio duplicate prime/quad; srad_v1 duplicates srad_v2; cholesky and ludcmp duplicate lu.

**Properties with thin or no coverage in these sources:** E9 has none verified. E2-B1a has only three solid rows (bfs, streamcluster, kmeans). The other E2-B1a rows need authoring or a seed fix.
