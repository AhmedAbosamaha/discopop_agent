DiscoPoP agentic controller

The Restructuring Loop

DiscoPoP profiles a program and reports the loops it cannot parallelize. The agent hands those to an LLM, which rewrites the source until the parallelism becomes visible — then gives it back to DiscoPoP to judge. Nothing survives unless the profiler can parallelize the rewrite and the result is measurably faster.

Start to finish

One region's whole journey — from the source file you start with to the parallelized one you end with. The profiler runs twice: once before the agent exists, and once inside the loop. Both runs are the same three commands.

start / end DiscoPoP does the work the agent decides the LLM does the work your source file is written

Why the profiler runs twice

This is the whole design. The LLM never decides whether it succeeded — DiscoPoP does, by being run again on the rewrite.

Run ① · before the agent

You compile with instrumentation, execute once to record the real dependences, then analyze. This produces .discopop/ — the agent never creates it and refuses to start without it.

Between the runs

The LLM sees the dependences that blocked parallelization and rewrites the region to remove them. It is forbidden to insert a pragma, so it cannot fake success — its output is still ordinary sequential C++.

Run ⑤ · inside the loop

The identical three commands, now on the rewritten file. If DiscoPoP finds no pattern in the lines the model touched, the rewrite achieved nothing and is reverted — passing the earlier checks only proved it did no harm.

The quality gate

Every candidate change is tested on a temporary copy before it reaches your file. Which stages run is decided by one thing only: whether the diff contains a pragma omp — not by which tier produced it. A Tier-2 rewrite has no pragma in it, so it is single-threaded, and the two thread-related stages would be asking the wrong question.

The skips are not a loophole. A Tier-2 rewrite still has to prove speed — just later, at the bottom of figure 1, once run ⑤ has produced a real pragma for it. Skipping the check there instead of here is what stops the agent asking a single-threaded file to be race-free.

Budget: what a failure costs

--budget (default 3) is the number of LLM attempts a region gets. One slot is charged at the top of every attempt. The distinction that matters is which failures are the model’s fault.

What each outcome costs the region
OutcomeMeaningCost
apply / compile / openmp_compile a build error — the idea may still be sound budget refunded · spends one of --build-retries (2)

Every one of those failures also reverts the source and the whole .discopop profile from a snapshot taken before the attempt, and sends the model a message naming the stage that failed. Only ok and exposed survive.

Depth: why the run terminates

Every accepted rewrite creates new candidates — the loops it just exposed — and adds them to the queue. Without a limit that is unbounded. --restructure-depth is that limit, and it defaults to 0.

Depth 0

Regions found by the first profile. Only these may be handed to the LLM at the default setting.

Depth 1+

Regions that only exist because a rewrite exposed them. They re-enter the queue and take the Tier-1 path, where WRITE ① adds the pragma — but they are not restructured again.

The deferral

Depth also picks when to judge the exposed pragma. If a deeper pass is still allowed, the agent accepts with verdict exposed and defers. At the default 0 there is no deeper pass, so the pragma is measured immediately.

The speedup gate

The last and strictest check, and the reason a plausible-looking rewrite still gets thrown away.

How it is measured

One binary, run two ways: OMP_NUM_THREADS=1 against unrestricted, in interleaved A/B pairs so drift in machine load hits both sides equally. The median is taken, not the mean.

The threshold

--min-measured-speedup, default 1.1×. Below it the verdict is no_speedup and the rewrite is reverted, even though it compiled, raced cleanly, and printed the right answer.

The second guard

The parallel build must also not be slower than the original program. Without this, a rewrite whose own sequential build is overhead-slowed could show a flattering ratio while actually losing.

Why this gate is not optional. A rewrite can pass byte-identical correctness while doing nothing at all — unrolling a loop, or adding a temp variable, leaves the operation sequence untouched and still serial. Text comparison cannot catch that. Measured speed can, which is why --require-speedup is on by default.
